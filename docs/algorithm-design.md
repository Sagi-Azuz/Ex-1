# תכנון האלגוריתם — הטלת מישור על נפח תלת־ממדי

## 1. מטרת האלגוריתם

האלגוריתם מקבל נפח תלת־ממדי `M` ומישור המוגדר באמצעות שלוש או ארבע נקודות במרחב, ומייצר תמונה דו־ממדית `E` המייצגת דגימות של ערכי הנפח לאורך המישור.

המסמך מתעד את החלטות התכנון שהתקבלו עד כה. החלטות שעדיין לא הוכרעו מופיעות בסעיף האחרון.

## 2. ממדי תמונת הפלט

נסמן:

- `Dab` — האורך של הכיוון שמוגדר על ידי `a` ו־`b`.
- `Dbc` — אורך הקטע `b`–`c`, המשמש לקביעת רוחב התמונה לפי האלגוריתם המקורי.
- `H` — גובה תמונת הפלט בפיקסלים.
- `W` — רוחב תמונת הפלט בפיקסלים.

בשלב התכנון הנוכחי נקבע:

- `H = max(1, round(Dab))`
- `W = max(1, round(Dbc))`

הפונקציה `round()` היא של Python. כאשר הערך מסתיים בדיוק ב־`.5`, Python מעגלת למספר השלם הזוגי הקרוב ביותר.

הבחירה בממדים שלמים נובעת מכך שמטריצת הפלט חייבת להכיל מספר שלם של שורות ועמודות. המינימום של פיקסל אחד מונע יצירת ממד ריק.

### מוסכמת האינדקסים

במימוש Python נשתמש במוסכמה המקובלת למערכי תמונה: `E[y, x]`, כלומר תחילה אינדקס השורה `y` (גובה), ואחריו אינדקס העמודה `x` (רוחב).

בפסאודו־קוד המקורי מופיע הסימון `E[x][y]`. לכן במימוש נבחר במפורש בסדר `E[y, x]`, ונקפיד שלא להחליף בטעות בין רוחב לגובה. הכיוונים הגאומטריים עצמם עדיין נקבעים לפי האלגוריתם של המטלה.

## 3. דגימה לאורך שורה

לכל שורה במישור נגדיר:

- `a1` — תחילת השורה במרחב התלת־ממדי.
- `a2` — סוף השורה.
- `d12` — אורך השורה.
- `N` — מספר הפיקסלים שיוקצו לשורה.

מספר הפיקסלים בשורה יחושב כך:

`N = max(1, round(d12))`

נקודות הדגימה יפוזרו באופן אחיד במרכזי הפיקסלים. עבור אינדקס פיקסל `i`, כאשר `0 <= i < N`, נגדיר את המיקום היחסי:

\[
u_i = \frac{i + 0.5}{N}
\]

נקודת הדגימה במרחב תהיה:

\[
p_i = a_1 + u_i(a_2 - a_1)
\]

כך נקודות הדגימה מפוזרות באופן אחיד לאורך השורה, וכל נקודה נמצאת במרכז התא המתאים לה ולא בדיוק בקצה השורה.

### הסיבה לבחירה

בפסאודו־קוד המקורי הדגימה מתחילה בקצה השורה ומתקדמת בצעדים של יחידת מרחק אחת. בתכנון הנוכחי מספר הדגימות מותאם למספר הפיקסלים שהוקצה לשורה, והדגימות ממוקמות במרכזי הפיקסלים. כך מתקבל מיפוי עקבי גם כאשר אורכי השורות הם מספרים שבריים.

### המשמעות והפשרה

זוהי סטייה מסוימת מהפסאודו־קוד המקורי, ולכן נבדוק את השפעתה על התוצאות. במידת הצורך נשווה אותה לשיטה שדוגמת גם את קצות השורה.

## 4. מיקום שורות בתוך התמונה

שורה עשויה להיות קצרה מרוחב התמונה הכולל. במקרה כזה נמקם אותה במרכז התמונה.

נסמן:

- `W` — רוחב תמונת הפלט.
- `N` — מספר הפיקסלים בשורה הנוכחית.
- `i` — האינדקס המקומי של הפיקסל בשורה.

האינדקס האופקי בתמונה יחושב כך:

\[
x = \left\lfloor \frac{W-N}{2} \right\rfloor + i
\]

השימוש ב־`floor` מספק היסט שלם ועקבי. כאשר אי אפשר למרכז את השורה בדיוק על רשת הפיקסלים, תיתכן סטייה של עד חצי פיקסל.

## 5. דגימת ערכים מתוך הנפח

לצורך קבלת ערך בנקודת דגימה בעלת קואורדינטות שבריות נשתמש באינטרפולציה טריליניארית. השיטה מחשבת ערך משוער באמצעות שמונת ה־voxels הסמוכים לנקודת הדגימה, תוך שקלול תרומתם לפי המרחק היחסי שלהם מהנקודה.

כללי הגבולות שנקבעו:

1. אם נקודת הדגימה עצמה נמצאת מחוץ לגבולות הנפח, ערכה יהיה `0`, בהתאם לדרישות המטלה.
2. אם נקודת הדגימה נמצאת בתוך הנפח אך חלק מה־voxels הדרושים לאינטרפולציה נמצאים מחוץ לגבולותיו, נתייחס לערכם של אותם voxels כאל `0` ונמשיך בחישוב האינטרפולציה הרגיל.

גישה זו שומרת על כלל אחיד לטיפול בגבולות, בלי להחליף שיטת דגימה סמוך לקצוות.

## 6. החלטות שעדיין דורשות השלמה

1. הגדרה סופית של מערכת הקואורדינטות של הקלט והמרתה לאינדקסי הנפח (למשל, קואורדינטות פיזיות לעומת אינדקסי voxel).
2. טיפול במקרים גאומטריים מיוחדים ובשורות בעלות אורך קטן מאוד.
3. הגדרה סופית של מבנה הפונקציות וממשקי הקלט והפלט.
4. בדיקות תקינות והשוואה בין תוצאות המימוש לבין התנהגות האלגוריתם המקורי.
5. אימות סופי של התאמת ממדי התמונה וסדר האינדקסים לדוגמאות הקלט ולדרישות המטלה.
